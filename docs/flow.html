cfa-rag: how it works

An ask-my-docs system for CFA Level I study notes. Select any step to see what it does, which technology it uses and what the alternatives were.

processing step gate: can refuse a question or fail a build not decided yet
The question flow is served over one HTTP API. It is built twice, in Python with LangGraph first and in Rust later (milestone 4), and judged by the same eval harness. Langfuse traces every step, and each conversation is one Langfuse session.

1 · Ingestion

Runs once, and again when the parser or the chunking changes.

Source PDFsinput

What: five SchweserNotes books and the QuickSheet, 1,151 pages.

Note: the notes are copyrighted and never enter the repository. A small openly licensed sample corpus lets anyone run the system.

↓
Parsenot decided

What: takes body text from the PDF text layer, converts formula images to LaTeX in reading order, and keeps every page number.

Why it is hard: the formulas are embedded images, so plain text extraction silently drops them.

Candidates: Docling; the text layer plus a model that reads only the formula images; Mistral OCR.

How it is decided: a bake-off on twenty pages. Output is kept per parser, so trying another never overwrites an earlier result.

↓
Chunkby structure

What: splits by reading, then by learning-outcome section, aiming for 500–800 tokens. Never splits a formula, a table or a worked example.

Each chunk carries: book, topic, reading, section, page range and kind.

Left out: quiz and answer-key chunks, so an answer key cannot pass as an explanation.

Alternative: fixed-size windows; they cut formulas in half.

↓
Embedbge-m3 + BM25

By meaning: bge-m3, run locally. It is multilingual, so a Vietnamese question can match English text.

By keyword: BM25 sparse vectors, for terms that must match exactly.

Alternative: embeddings from an API; they cost money and send text to a vendor.

↓
IndexQdrant

What: both vectors for each chunk live in one Qdrant collection, so one query can search both.

Python service: Qdrant runs inside the process. Rust service: a Qdrant server in Docker.

Alternatives: LanceDB, Chroma, Weaviate.

2 · Question flow

Runs for every question.

Chat UIStreamlit

What: two columns, with the chat on the left and the sources on the right. A conversation list sits in the sidebar.

Citations: numbered buttons under the answer; selecting one shows the passage with its book, reading and page.

Alternative: a React frontend, later. The UI holds no retrieval logic, so it can be replaced.

↓
Service APIFastAPI

What: the only way into the question flow. Asking a question returns a stream of step events and then one result, either an answer or a refusal.

Contract: an OpenAPI file. Contract tests run against any base URL, so the Rust service must pass the same ones.

↓
Input checkgate

What: strips control characters and rejects empty input or input over 2,000 characters.

Limit: it is not an attack detector. It is the first of several layers.

↓
Rewritelocal model

What: turns the question and the last few turns into one standalone English question, and notes which language the user wrote in.

Why: “what about annuities?” cannot be searched on its own, and the notes are in English.

Only this step sees the conversation history.

↓
Hybrid search20 chunks

What: searches by meaning and by keyword at once, and merges the two rankings by rank (RRF) rather than by raw score.

Why both: meaning finds paraphrases; keywords find exact terms and formula names.

↓
Rerankkeep 5

What: a cross-encoder reads the question together with each chunk and scores how well they match.

Technology: bge-reranker-v2-m3, run locally. Alternative: Cohere Rerank.

It is kept only if it improves retrieval over hybrid search alone.

↓
Grounding gategate

What: if the best reranker score is below a threshold, the system declines without calling the answering model.

Threshold: calibrated on part of the golden set, not set by feel.

↓
AnswerOllama, Claude later

What: the model writes statements from the five chunks only. Each statement carries a chunk id and a verbatim quote.

Against injection: the question and the chunks go into the prompt as labelled data, and the prompt says so. The prompt lives in a versioned file.

↓
Citation checkgate

What: code checks that each statement has a citation, that the chunk id is one of the five, and that the quote really occurs in that chunk.

On failure: regenerate once, then decline.

Limit: it proves the quote exists, not that it supports the statement. That gap is what the faithfulness metric measures.

↓
Respondsaved + traced

What: shows the answer with its sources and saves the turn. The answer is shown only after the citation check, so it is not streamed word by word.

Rendering: plain Markdown with raw HTML, images and links removed.

3 · Evaluation

Before every change, and in CI.

Golden setwritten by hand

What: questions with reference answers and supporting pages, questions the notes cannot answer, and prompt-injection attacks.

Public, with a rule: every item is in the author's own words with page references only, never text copied from the notes.

↓
Run the question flowsame API as the UI

What: every question goes through the HTTP API the UI uses. There is no separate path for evaluation.

Why: the same harness can judge the Python service and the Rust service by changing a base URL.

↓
Scoretwo kinds

Without a judge model (gated): retrieval hit@5 and MRR@10, citation-check pass rate, refusal accuracy in both directions, attack success rate.

With a judge model: faithfulness and answer correctness (DeepEval). Reported, but not gated until the judge agrees with hand labels.

↓
ReportLangfuse

What: each result records the git commit, a hash of the config and the prompt versions, and goes to Langfuse so runs can be compared.

Committed reports hold ids and scores only, never text from the notes.

↓
CI gategate

What: a pull request that lowers a gated metric below the recorded baseline minus a tolerance fails the build.

Limit: GitHub's runners have neither the notes nor a local model, so CI runs on a small sample corpus. The full run happens on the author's machine.
